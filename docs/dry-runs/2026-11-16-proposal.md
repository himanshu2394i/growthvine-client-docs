# Dry run: allocation proposal from two real advisor PDFs (16 Nov 2026)

Followed the skill literally from "use Growthvine" to a finished PDF and PPT,
playing the advisor, with a real client's "Investment Options" and "Investment
Plan" PDFs (client anonymised here; files kept out of the repo).

Result: a 16-scene cinematic proposal in both formats; every figure passes
`verify.py`. Along the way the run exposed these gaps, all fixed:

| # | Finding | Fix |
|---|---|---|
| F1 | Risk label differed between documents ("Moderate to High" vs "Growth Oriented"), not caught | `profiles` in inputs.json; reconcile flags `profile_conflict` |
| F2 | Options at fund level, master table at strategy level; B5 assumed one level | QUESTIONS.md: named funds = detail, strategy table = summary; confirm |
| F3 | Liquidity only per strategy row; a second-option holding had no row | QUESTIONS.md C2: inherit by matching rows; ask for unmatched holdings |
| F4 | Master table keyed by bucket + asset class + vehicle couldn't be entered | reconcile: `rows.field` may be a list |
| F5 | "33%" flagged as wrong vs 33.3% (false alarm) | reconcile judges % at its printed precision |
| F6 | Summary tables described Option 1 only; nothing said to work that out | QUESTIONS.md: match tables to options by totals; ask if unclear |
| F8 | No guidance on recording "document A is right, B is outdated" | inputs.md: correct to the confirmed version, add a `note` |
| F9 | Files never say regular vs direct; costs/returns differ a lot | QUESTIONS.md C4, required when fund data is shown |
| F10 | Advisor short names ("Nippon Multi Asset") miss the official name; near-twins exist | QUESTIONS.md: search distinctive words, confirm every match |
| F11 | Advisor labelled a fund "Large Cap"; the match is an "Ex-Top 100" fund | Confirm matches; contradictions go to the second opinion |
| F12 | `search_schemes` rows carry no as-of date | data.md: use `get_data_freshness`, record in `fund_data` |
| F13 | verify.py flagged real fund-data returns | `fund_data` in inputs.json, accepted by verify |
| F14 | **Long table cells were silently cut to one line** | Renderer wraps cells, sizes columns to content, errors if it can't fit |
| F15 | A headline ("moves ₹70 L into the AIF") was misleading; ₹70 L passed verify as a valid sum elsewhere | Confirms the re-read step in CHECK.md B is needed; verify can't judge wording |

Not tested here: a genuinely fresh reader (the author ran it), claude.ai upload
and its Python environment. Next: run it on claude.ai from the zip.

## Round 2: using the fund data fully (same day)

Rebuilt the proposal with full v3 fund data (5 holdings covered): 27 scenes with
a market snapshot, returns vs Nifty 500 TRI, a 5-year growth chart, look-through,
overlap, projections, and one page per fund. Every figure passes `verify.py` in
PDF and PPT. New findings, all fixed:

| # | Finding | Fix |
|---|---|---|
| F17 | Old MCP tools are frozen and scheduled for removal | data.md uses v3 tools only |
| F18 | Index ends 26 Oct, NAVs (month-ends) run to 13 Nov; comparing across dates is unfair | `analyse.common_end`: latest date every series has (30 Sep) |
| F19 | 30 Sep minus 6 months landed on 30 Mar, missing the 31 Mar month-end | Month-end aware date shifting |
| F20 | A hedged SIF lists 39.7% gross shares but -0.33% net equity | Hedged funds left out of look-through/overlap and named |
| F21 | Raw exit-load text was long and garbled, overflowing the fund page | Summarise long factsheet text faithfully, numbers unchanged |
| F22 | Layout overflow printed a Python traceback | CLI prints a plain message, exit 1 |
| F23 | Figures written into explanation text weren't recorded; a made-up "30%" rule of thumb | verify caught both; CHECK.md says record real ones, reword invented ones |
| F24 | "3.5-year" flagged as a stray number | verify skips hyphenated durations |
| F25 | PPT line chart labelled all 61 months; first fix put the XML setting in an invalid position | `tickLblSkip` inserted in schema order (PowerPoint honours it; LibreOffice ignores it) |
| F26 | Index CSV capped at 1,000 rows; responses must be re-typed into files | data.md: fetch in ranges, save month-ends and equity holdings only |

## Round 3: content-heavy, insight-led (after review)

Feedback: notes talked about missing data instead of interpreting the data;
too few charts and too much white space; "·" separators everywhere; only
Option 1's holdings shown; the MCP's CSV export wasn't used. Rebuilt as a
23-scene proposal of mostly 3-4 panel pages, verified in PDF and PPT.

| # | Finding | Fix |
|---|---|---|
| F27 | Notes narrated data gaps ("these funds don't publish...") | DESIGN.md: comments interpret the data shown, CFA-style; gaps are the advisor's choice, never narrated |
| F28 | Sparse pages, one chart each | `panels` scene (2-4 panels: bars, donut, stack, table, text, stats, line, plus a number strip); content-heavy is the default |
| F29 | "·" separators in kickers, footers, credits | Validation rejects "·" anywhere; renderers use commas |
| F30 | Only Option 1's holdings were shown when comparing | DESIGN.md: show every option's holdings |
| F31 | JSON re-typing was heavy | MCP CSV exports (`find_funds`, holdings and NAV history) read directly by analyse.py |
| F32 | An inline company-size calculation counted a missing field as zero (29/15/15 instead of 55/24/22), and verify passed because the wrong figures were recorded as the source | `analyse.size_split`, tested; all calculations live in analyse.py |
| F33 | A hand-subtracted gap (₹1.29 Cr) was wrong; verify caught it (₹1.28 Cr) | Figures come from calculations, never mental maths |
| F34 | Units in capital panel titles ("₹3 CRORE") weren't recognised by verify | Case-insensitive units |
| F35 | Quarter-page panels overflowed with long tables or bullets | Text panels shrink a step; tables trimmed; clear error otherwise |
| F36 | Short columns wrapped ("5+ years") | Column widths keep room for their longest word |
| F37 | PPT negative bar labels hid the category labels | Category labels anchored low |
